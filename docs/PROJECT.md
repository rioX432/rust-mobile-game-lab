# SEED Race | 現行プロジェクト方針 v1
更新: 2026-10-24 / Parent Epic: [#16](https://github.com/rioX432/rust-mobile-game-lab/issues/16)

## 成功させたいこと
SEED系の小さなオリジナルキャラが立体的なコースで滑る・跳ねる・衝突する物理レースを作る。配信者はゲームを始めて実況し、視聴者はスマホで短い操作だけで参加できる。自分の出場・名前・順位・勝敗がわかり、同じ部屋で再戦できる。

*Marbles on Stream*から参考にするのは **低負担の参加・多数の出場者・実況との相性** だけ。既存ゲームの素材・コース・UI・商標・音声・ソースはコピーしない。ゲーム名「SEED Race」は仮名。Avvyアバターの表示は必須ではない。

## キャラクターとゲーム
ユーザーが提供したSEED系リファレンスには seed / noppo / maru / nagi / koro / saya / goma / futa / sumi / shiro の10体と、idle / dead / win の表情がある。**造形や色を勝手に変更しない。** 初期開発はseed1体で2D/3Dを比較し、量産は実ゲームでの美術評価後。公平性のため外観とColliderを分離し、原則同じ物理特性から開始する。deadは演出上の脱落表現候補であり、通常の接触で使わない。

## 優先するゴール
1. **技術比較**: 既存2D Rust共通基盤を壊さず、3Dレンダラー/物理候補をAndroid/iOSで比較。
2. **最初の完成体験**: 独自コース1つ・SEED基準キャラ1体・20個の参加オブジェクト・10〜20秒ほどの物理レースをオフラインで実際に遊ぶ。カメラ・結果・再戦までつなぐ。
3. **参加体験**: 配信者がルーム作成・スタート、視聴者がAndroid/iOSから入室、同じ順位・途中参加/再接続を確認。
4. **仕上げ**: 見た目/FX/音/UIを制作・比較し、実機性能、サイズ、負荷、権利を検証。
5. **変化への対応**: サーバー側Luaをラウンド単位で切替し、既存Rust物理を再ビルドせずルール変更できる範囲を検証。

## 当面やらないこと
- Avvyの本番persona-*や配信バックエンドへの結合、アバター描画の移植
- 汎用ゲーム制作ソフト/エディタ、2本目の「3択投票」制作の優先化、キャラ10体の一括3D化
- 外部ゲームのクローン資産、本番ギフト/課金/認証、App Store/Play公開、商用ライセンス未確認素材の配布
- Luaへのフレーム単位の物理処理の移動、任意Native API公開、Public GitHubでPrivate制作物の再配布

## 判断が必要なもの
- **3D表現**: 同一シーンでwgpu最小3D vs Bevy等を比較 (G03)。3D成立が弱ければ2.5Dも選択。
- **アート**: 2D billboard vs 3Dトゥーン、からくり玩具/その他ステージ案は試作・比較で採用 (G04/G05)。未採用案を正本化しない。
- **原画の権利と公開範囲**: 未確認。公開前に明示検証 (G04)。
- **実機環境と性能予算**: G14で初めて測定。60fpsは目標であり測定済みの事実ではない。

旧オフラインPoCの成果は[offline-native](offline-native.md)と[PR #15](https://github.com/rioX432/rust-mobile-game-lab/pull/15)。2026-10-24時点でオフライン3択を超える機能の実装完了は主張しない。
