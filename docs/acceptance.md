## 自動検証

- 状態遷移、同seed/入力列の再現、境界値。
- ホスト権限、重複/旧ラウンド/締切境界の入力拒否。テスト時刻は注入する。
- スナップショット復元、途中参加、切断・再接続。
- FFIのnull/無効ID/二重破棄/破棄後入力、panic境界、Surfaceの寿命。
- 実サーバーと複数の実クライアント。約20合成参加者を実機20台とは扱わない。
- Rust fmt/clippy/意味のあるテスト、Androidビルド、macOSでiOS SimulatorビルドをCIで実行。LLM呼び出しを入れない。

## 性能の記録条件

Release相当（LAN例外は内部測定構成のみ）、端末/OS/GPU/解像度/10個と100個の描画駒/測定区間を記録。
60 FPSを初期目標に約5分のフレーム提示間隔・CPU時間・メモリ推移・画面表示開始時間を分けて測る。
可能な入力反映時間・往復時間、最適化条件とサイズ差分を記録する。測れない数値を推定で埋めない。

## 順序とレビュー

最小描画・タッチ・Surface再生成の両OS埋め込み → オフラインレース → 通信 → 投票/SDK → 最終検証。
重点レビューはネイティブ/FFI寿命、通信復帰、両ゲーム/SDKの3回。重大な指摘を修正して関連検証を再実行する。

オフラインの実行条件・画像・記録は[docs/offline-native.md](offline-native.md)。動的な密度変更と全phaseでの復帰は未確認。2026-10-24にrioが今回の到達範囲をオフラインまでと選択したが、PoC全体の必須条件を満たした扱いにはしない。
